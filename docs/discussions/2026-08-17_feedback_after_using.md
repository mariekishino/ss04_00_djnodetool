## 1. ウィンドウの境界をドラッグしてリサイズしたい

- Track Library と Canvas の境界 → 横幅を調整
- 下部デッキと Canvas / Track Library の境界 → 高さを調整

現在はすべて固定幅・固定高さ(左サイドバー 260px、デッキは内容依存)。境界にカーソルを合わせるとリサイズできる形にしたい。

**論点**: 調整した幅をプロジェクト JSON に保存するか、ブラウザに覚えさせるか、セッション限りにするか。プロジェクトの内容ではなく作業環境の設定なので、プロジェクト JSON に入れるのは筋が悪い可能性がある。

## 2. キャンバスだけを拡大・縮小したい

現在トラックパッドの操作ではブラウザ全体が拡大縮小してしまう。キャンバス内だけをズーム・パンしたい。

**論点**: ノードの座標(`x`, `y`)は CSS ピクセルとして保存されている(2026-06-10 の決定)。ズームを入れると「画面上の位置」と「保存される位置」が別物になるため、ドラッグ移動・エッジの描画・波形クリックなど座標を扱うすべての箇所に影響する。単独のフェーズとして扱うのが妥当。

## 3. ノードで繋いで再生してもトランジションが起きない(疑問)

> Start Connection でノードを繋いだが、再生しても曲の終わりから次の曲へ自然に繋がらない。トランジションは Play Transition を押したときだけ起きる。これはなぜか。

**回答**: 繋いだ曲を順番に流す機能は実装済み(Phase 12)だが、それが起きるのは「**Play from here**」で始めたときだけ。「**Play**」は選択した1曲だけを鳴らし、繋がりを辿らない。

ただし、これは**使う側の間違いではなく UI の問題**として扱うべき:

- ボタン名が「Play」と「Play from here」で、どちらが繋がりを辿るのか一目で分からない
- 仮に Play from here を押しても、トランジションが起きるのは**曲の終わり際**。4分の曲なら4分待つ必要があり、実際には体験できない
- つまり「機能はあるが、確かめる手段が実質ない」状態

**改善案**:

- ボタンの表記を機能が伝わるものにする(例: 「この曲だけ再生」/「ここから順に再生」)
- 6番(トランジション位置の指定)が入れば、曲の途中で繋ぎを試せるようになり、この問題はかなり軽くなる
- 「今すぐ次の曲へ移る」ボタンがあれば、待たずに繋ぎを確認できる

## 4. 曲名・波形がキャンバスに反映されない

**曲名の件**は既知の課題。`docs/discussions/2026-08-17_open_issue_track_audio_identity.md` に記録済み(トラックのカード内プルダウンで音源だけを差し替えると、タイトル・アーティスト・BPM が古いまま残る)。

**波形の件は新しい不具合(このメモで判明)**:

`WaveformCache` はトラックIDと幅をキーに波形をキャッシュする。音源を差し替えたときにキャッシュを捨てる `forget()` を用意してあるが、**どこからも呼んでいない**。そのため差し替え後も**前の音源の波形が表示され続ける**。

- 原因箇所: `src/App.tsx` の `handleChooseServerFile` / `handleImportTrackAudio` が `WaveformCache.forget(trackId)` を呼んでいない
- 修正規模: 2行程度
- 影響: 音源を差し替えたときのみ。新規トラック追加(推奨経路)では起きない

なお、開発者の指摘「**キャンバスに載せた時点で正しい情報を反映すべき**」は、この2件に共通する本質。トラックの情報と実際の音源が一致していることを、どこで保証するかという設計の問題として、既存の課題記録と合わせて詰める。

## 5. Inspector の位置と一時停止ボタン

- Inspector を、下部の2つのバーの間に配置してはどうか
- **一時停止ボタンが無い**ので追加したい

**補足**: 現在あるのは Stop(停止)のみで、一時停止は未実装。Web Audio では `AudioContext.suspend()` で全体を止める方法と、位置を覚えて停止・再開する方法がある。前者は簡単だが、連鎖再生のタイマー(通常の時計で動いている)と足並みが揃わないため、**タイマー側も止める対応が要る**。単純に見えて連鎖再生との整合が論点になる。

## 6. トランジションする場所を選びたい

**第3段階として実装予定**(`docs/plans/` に設計書はまだ無い)。「曲Aのここから抜けて、曲Bのここから入る」を波形上で指定する。Phase 17 のシークで「波形上の一点を指定する」土台はできているので、それを2点に広げる形。

## 7. 次の曲を下のバーに反映したい

**Phase 16 で実装済み**。下部の NEXT デッキが、ノードの繋がりを辿った次の曲を表示する(要望の内容とほぼ同じ)。

ただし表示されるのは**現在のノードから出ているエッジがある場合のみ**。繋がりの終端のノードを選ぶと「—」になる。確認されたときに NEXT が空だった場合、この条件に当たっていた可能性がある。次回、繋がりの始点側のノードを選んで確認する。

なお NEXT デッキが何を出すかのルール自体は暫定で、`docs/discussions/2026-08-17_open_issue_next_deck_selection.md` に未解決として記録済み。

「次の曲がどこから始まるべきか準備しておきたい」という要望は 6番(トランジション位置の指定)と一体で、NEXT デッキ上で入りの位置を指定する形が自然。
